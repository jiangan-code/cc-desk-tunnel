# 同一服务的多设备执行通道（0.2.6 / 协议 13）

新版 Linux / macOS 终端客户端 ccdt 可同时连接同一服务：Linux 电脑和 Mac 各自持有执行通道，即使项目路径相同，也只在各自设备上执行。每个设备最多启动 8 个原生终端。设备离线后，其会话保留在原设备名下；其他设备无法代为执行。

## 身份、认证与路由

- 服务令牌验证通过后，客户端使用设备 ID（UUID）和独立的 256 位随机设备密钥注册或验证身份。首次注册建立绑定，后续相同 ID 使用不同密钥会收到 `device_unauthorized`，不会覆盖旧绑定。服务端只在 SQLite `devices` 表保存密钥的 SHA256。
- 客户端原子写入 `device.json`：ccdt 在 `~/.config/cc-desk-tunnel/`（服从 XDG_CONFIG_HOME）。文件在 POSIX 系统权限为 0600。`ccdt device` 只显示 ID。身份文件损坏时要求恢复备份，不自动更换身份；新电脑应生成自己的身份，不复制旧设备文件。
- 稳定设备 ID 与每次连接的 `connectionId` 分开。服务端按设备保留执行通道租约；同一设备正常重复登录收到 `device_busy`，不会踢掉现有在线连接。辅助控制连接可使用同一设备证明，但不因此取得执行通道。
- 新版 Linux / macOS ccdt 使用独立 WSS relay，不占用 frps 端口。原有桌面客户端保留独占兼容模式，本次不扩展其多设备行为。
- relay 绑定同时验证连接 ID、该连接随机生成的 relay 密钥、稳定设备 ID 和设备密钥。A 即使知道 B 的连接 ID 和 relay 密钥，使用 A 的设备证明仍被拒绝。认证、续接、relay 都经过原有 TLS / 指纹验证；身份数据不经过渲染页，也不写入普通日志。
- `session_devices` 将会话绑定到设备。列表、订阅、历史、创建请求幂等、分叉、改名、删除、导出、运行与终端控制均校验归属；更新广播、事件和逐次用量记录也按归属过滤。相同项目路径不会作为跨设备匹配条件。分叉继承设备归属。
- 每个运行/终端保存所属 Peer，SSH 使用该 Peer 的通道。终端状态回调使用每个终端独立的随机密钥。

设备凭据保护的是服务协议的资源访问。服务仍是同一可信用户使用：Claude 账号、提供商配置、全局设置、账号额度和聚合统计共用；原生 Claude 进程仍在同一服务端系统账户下运行。拥有该账户的任意代码执行能力可读取它可访问的文件，因此这一设计不提供互不信任租户的操作系统隔离。

## 掉线、续接与清理

短暂掉线继续使用原来的连接 ID、续接密钥和帧计数；服务端还会核对稳定设备身份，不能用 A 的设备证明恢复 B 的连接。恢复时只替换原 Peer 的 socket，运行和通道不迁移给其他设备。

进程重开后不能重放旧帧时，同一设备凭据可以接替自己的已掉线连接。服务端先预留新租约，取消旧运行并等待旧终端/通道清理完成，再发送 ready。每个清理回调只在 Map 中仍指向自己时才删除租约。旧 socket 的迟到 close 回调若已不再拥有当前 socket，直接忽略。

超过宽限期后，A 的执行通道与进程按原有语义结束；A 后续以稳定身份重新连接，仍只能看到自己的会话。新版桥沿用原先的严格原生 `--resume <id>` 恢复，不把未知工具结果当作成功，也不重放有副作用的命令。B 的连接、终端和 relay 不参与 A 的清理。

## 旧客户端与历史数据

协议 13 的服务同时接受协议 12 的旧客户端。旧客户端没有设备证明，使用保留的 `legacy` 归属，只能独占服务，不能与带设备身份的连接混用。冲突返回 `legacy_device_exclusive`，并明确要求升级旧客户端。旧客户端的 ready 仍使用协议 12。

新客户端发送设备证明，不会自动降级成无身份客户端；连接旧服务会明确失败。先升级服务端，再升级各执行客户端，才可同时在线。

首次打开旧数据库时，仅增加 `devices` 和 `session_devices` 表，将原会话归到 `legacy`；不根据登录顺序或路径自动认领。新 Mac 不会看到旧电脑的历史。管理员应在停服、备份后，明确将旧会话分配给旧电脑的已注册 ID：

```bash
# 在旧电脑的新客户端上查看 ID，只输出公开的 UUID
ccdt device

# 在服务停止后，用 Node.js 24 在部署源码目录执行
node scripts/assign-device-sessions.mjs \
  --offline --data-dir /srv/cc-desk-tunnel/state --device-id <旧电脑设备ID>
```

该工具只分配 `legacy` 会话，目标必须已注册；事务提交，重复执行分配数为 0。原生会话分叉共享目录，工具检查同一目录族不能被拆给不同设备。源会话和原生记录不重写。

## 测试环境验证、升级与回滚

1. 在独立数据目录启动服务并运行测试。真实服务升级要安排任务停止窗口；首次重启会结束旧进程，现有会话记录可恢复。
2. 确认生产升级窗口后，用现有 `manage.sh backup` 备份完整持久化数据，另存原程序与镜像。预留备份磁盘空间。
3. 上传本版本服务端包并运行 `manage.sh upgrade --from <包路径>`。本次工作不执行生产升级。
4. 安装 0.2.6 客户端。旧版与新版不能混用；先关闭旧客户端，使用新版 `ccdt accounts --json` 完成设备注册和服务验证，不启动模型任务。
5. 如有旧历史，停服并按上面的命令分配给旧电脑的 ID。未在 VPS 安装 Node 时，可在停服后使用已有服务镜像运行离线工具（卷路径按部署调整）：

```bash
docker run --rm --entrypoint node \
  -v /srv/cc-desk-tunnel:/data \
  -v /opt/cc-desk-tunnel/scripts/assign-device-sessions.mjs:/tools/assign.mjs:ro \
  cc-desk-tunnel:local /tools/assign.mjs \
  --offline --data-dir /data/state --device-id <旧电脑设备ID>
```

6. 启动服务，分别连接旧电脑和 Mac；两边核对各自目录和标记文件，再开始任务。ccdt 升级后需重启其后台服务以加载新代码。

回滚时先停止新版设备连接和服务，恢复旧镜像/程序及升级前的完整数据备份，再启动旧版单设备客户端。旧服务不会理解设备归属表，不能只回滚镜像后继续让多台设备连接。回滚到备份会舍弃备份之后产生的记录，应先另存新版数据。

## 自动化验证的实际范围

`apps/desktop/test-main/multi-device.test.mjs` 使用真实服务、TLS/WSS、生产 relay 模块、OpenSSH、Bash 文件操作和 PTY。主要用例通过模拟设备连接、两个隔离的临时目录命名空间、无模型的 CLI 替身，验证同路径归属、并发读写与输出、掉线/退出/延迟清理、越权拒绝和严格原生对话恢复。CLI 替身读取服务实际生成的 SSH 提示，执行真实 SSH 命令。

另有一项直接运行两套 ccdt 使用的生产 `openProxyBridge`，验证持久身份和同时接入；身份文件并发发布、数据库重启和旧数据离线分配另有专项测试。现有单设备与断线续接回归继续执行。

这些测试未启动完整 Electron 客户端、未在真实 Mac/Windows 上运行，也未调用模型。跨真实设备的人工验收需再验证 macOS 后台服务及模型工具调用；模型验收会消耗账号额度，应在用户同意后进行。
